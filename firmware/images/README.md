# Slide Artwork

| Slide | Source | Embedded asset |
|---|---|---|
| Business card | `business_card.png` | `business_card.rgb` |
| LinkedIn QR | `linkedin_qr.png` | `linkedin_qr.rgb` |

The PNGs retain the artwork from the working prototype. Source images are 480 x 320 landscape pixels. Conversion rotates them 90 degrees counter-clockwise into the panel's native 320 x 480 layout.

Each RGB file contains 460,800 bytes: red, green, and blue per pixel, row by row, without a header or padding. Both assets total 921,600 bytes and are linked into flash. Rendering masks channels to RGB666 through a shared 960-byte buffer. The QR slide uses an additional 960-byte temporary row to composite its colors at draw time.

## Regenerate Assets

Run from the `firmware` directory:

```text
python -m pip install -r tools/requirements.txt
python tools/convert_image_to_rgb.py images/business_card.png images/business_card.rgb
python tools/convert_image_to_rgb.py images/linkedin_qr.png images/linkedin_qr.rgb
python -m unittest discover -s tools/tests -v
idf.py build
```

Conversion requires Pillow; normal firmware builds use the saved RGB files. Commit the source and regenerated asset together when artwork changes. Tests compare generated bytes against the saved assets to catch outdated conversions.

The converter rejects dimensions other than 480 x 320 and multi-frame images. It preserves pixel positions without resizing or filtering and composites transparent pixels onto white. This avoids changing QR module geometry during conversion. Scanning still needs validation on the physical screen.

References: [Pillow image operations](https://pillow.readthedocs.io/en/stable/reference/Image.html) and [ESP-IDF embedded binary data](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32c3/api-guides/build-system.html#embedding-binary-data).

## QR Presentation

The QR slide uses the business card's corner color as its gold background. Its white panel is blended at 25 percent opacity over that gold while the black QR modules remain unchanged. This is composited into RGB pixels during drawing; the LCD does not use an alpha channel.

The original QR PNG and RGB asset remain unchanged. The panel occupies landscape coordinates x=105..374 and y=25..294, corresponding to native x=25..294 and y=105..374. If the QR layout moves in replacement artwork, update these bounds in `main/slides.c`. The shared `slides_read_region` path applies the same colors to full QR rows and animation tiles.
